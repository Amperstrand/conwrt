# conwrt serial-watch — Prior-Art Research Report

**Date:** 2026-10-25 · **Scope:** design-pattern mining for `conwrt serial-watch` (PR Amperstrand/conwrt#545) · Research-only pass; no repos modified.
**Method:** direct fetch of upstream docs/repos (OpenOCD manual, esptool docs, RAUC docs, SWUpdate docs, labgrid docs, OpenWrt repo, mfgtools, pexpect docs) + web search for novelty scan. (zread/web-search MCP unavailable in this session; equivalent coverage via direct fetches + DuckDuckGo HTML.)

**conwrt modules referenced below:** `transport` (serial / tcp+telnet-IAC), `classifier` (U-Boot/Linux/booting/silent), `recipe-engine` (JSON recipes, triggers, echo-proof markers), `fire-state` (on-disk cross-process state), `verify-gates` (on-box sha256), `tftp` (bundled read-only server), `raw-transfer` (chunked serial fallback), `flash-rescue` / `serial-detect` (device card: env/kernel/release/MTD).

## 1. OpenOCD — "detect, understand layout, talk to anything"

Sources: OpenOCD User's Guide, *Config File Guidelines* (https://openocd.org/doc/html/Config-File-Guidelines.html), project docs at https://openocd.org/doc/html/, repo https://github.com/openocd-org/openocd.

OpenOCD is universal because **configs are programs, not data** (embedded Tcl), organized as a composable fragment library with a strict declare-then-init lifecycle.

### Stealable patterns

| # | Pattern | OpenOCD implementation | conwrt mapping |
|---|---|---|---|
| 1.1 | **Config fragment hierarchy + `find` search path** | Shipped library split into `interface/` (adapter), `target/` (chip), `board/` (wiring, DRAM/PLL init, external flash). Board files do `source [find target/stm32f4x.cfg]`; `find` resolves against a search-path so user dirs override shipped ones. | `serial-detect` device cards: split into `chip/realtek-rtl8382m.json` → `board/zyxel-gs1900-8hp.json` → revision overlays. Add a `find`-style resolver (shipped cards dir + `~/.config/conwrt/cards/`). MTD layout lives at chip level; env quirks/prompt strings at board level. |
| 1.2 | **Two-phase lifecycle: config stage vs run stage** | Config files only *declare* (they "can't use TAPs or targets… can't even verify that a flash chip is present"). `init_targets` / `init_board` procs run only after `init`, when hardware is reachable. Overrides chain: a "more specific" file re-sources and replaces `init_targets`. | `recipe-engine`: separate **load/validate** (schema, cross-refs, card match) from **arm/run** (attach console, install triggers). Concretely: `conwrt serial-watch --recipes dir` should fully validate + lock recipes *before* opening the port, so a config error never costs you the 1 s bootdelay window. |
| 1.3 | **Lifecycle event hooks** | `$_TARGETNAME configure -event reset-start { adapter speed 100 }` / `-event reset-init { enable_fast_clock; adapter speed 10000 }` / `-event reset-deassert-post …` — user Tcl fires on *state transitions*, with the canonical "slow clock until init, then speed up" doctrine. | `classifier`: expose `on_enter_uboot`, `on_enter_linux`, `on_boot_start`, `on_silent_timeout` as first-class trigger types alongside signature matches. Speed doctrine analog: conservative pacing (small chunks, low baud) until prompt is confirmed, then aggressive transfer. |
| 1.4 | **Detect-with-assertion** | `jtag newtap … -expected-id $_CPUTAPID` — on examine, actual IDCODE is compared to declared expectation and mismatches produce a precise, named error (mfg/part/ver of expected vs got). | `serial-detect`: card carries `expect` block (prompt regex, `U-Boot 20xx.xx`, SoC string from `/proc/cpuinfo`, MTD sizes). Detection should end with an **assertion report**: matched card, per-field confidence, explicit mismatch text. Prevents flashing a GS1900-10HP card onto a -8HP. |
| 1.5 | **Network control surfaces as product features** | OpenOCD exposes telnet :4444 (command), Tcl :6666, GDB :3333 — external tooling integrates *through the running supervisor*, not by re-implementing it. | `serial-watch`: add a small TCP/JSON control port (`--listen :7331`): `state`, `fire <recipe>`, `events` (subscribe). This is what makes labgrid/AI integration cheap later (see 5.1, and improvement #8). |

Bonus worth stealing later: **work areas** — OpenOCD downloads small code snippets to target RAM to accelerate flash ops (cf. esptool stub, 2.2).

## 2. esptool — chip detection, pacing, stub flashing, transfer integrity

Sources: https://docs.espressif.com/projects/esptool/en/latest/esp32/advanced-topics/serial-protocol.html (fetched in full), https://github.com/espressif/esptool (README), flasher stub repo https://github.com/espressif/esp-flasher-stub.

### Stealable patterns

| # | Pattern | esptool implementation | conwrt mapping |
|---|---|---|---|
| 2.1 | **Detection with documented fallback chain** | SYNC frame (36-byte magic) at 115200; chip ID via `GET_SECURITY_INFO` where supported, else **magic-value registers** at known addresses; if even that fails → conclude "secure download mode". Every fallback is documented per-chip. | `serial-detect`: publish the detection ladder per state (U-Boot banner → `version`/`printenv` probe → Linux `cat /proc/cpuinfo` + `/proc/mtd`) and **emit a terminal reason** ("silent: no banner in N s at baud X") instead of just "unknown". Confidence-scored card match, like 1.4. |
| 2.2 | **Stub loader: upload a tiny helper into target RAM** | esptool loads a flasher stub to IRAM; stub announces itself with an unsolicited `OHAI` packet, then replaces the ROM protocol with a faster, more regular one (JIT erase, big blocks, windowed reads). | `raw-transfer`: after first shell/U-Boot contact, stage a **busybox-only on-box helper** (a static `sha256sum`+`dd` script, or a tiny C helper) via the chunked channel; subsequent verify/erase/read steps run on-box with no host round-trip. Your on-box sha256 gate is already half of this; formalize "stage helper → OHAI-style proof → switch to fast mode". |
| 2.3 | **Layered integrity: weak per-block + strong final** | Every `FLASH_DATA` block carries a seq number and XOR checksum; the docs state plainly this is *"not adequate to ensure valid data"* → `SPI_FLASH_MD5` over the written range is the real gate and is "recommended that this command is always used". | `raw-transfer`: add per-chunk **sequence + CRC32** ACKs (retry chunk, not file), and keep the final whole-image on-box sha256 as the authoritative gate (already have). Adopt the doctrine in docs: block checksum = transport hygiene, range hash = truth. |
| 2.4 | **Windowed ACK flow control + negotiated parameters** | Stub `READ_FLASH`: host sets packet size and **max un-acked packets in flight**; acks are byte-count totals; transfer ends with an MD5 of everything. Baud: sync at 115200, then `CHANGE_BAUDRATE` and *test* before proceeding. Block size 16 KB chosen to fit target RAM. | `raw-transfer`: negotiate chunk size + in-flight window with the on-box side (echo-marker = ACK today; make it explicit), support resume-from-offset (chunk ledger in `fire-state`), and add baud up-shift with test-and-fallback for the TFTP-less path. |
| 2.5 | **Pre-flight image gates** | esptool refuses images whose chip/revision/flash-size don't match the detected part before writing; `image_info` validates header/checksums offline. | `flash-rescue`: parse the OpenWrt image *before* transfer — target profile string, kernel/rootfs sizes vs the device card's MTD layout, architecture vs card CPU. Fail fast, outside the death window (see SWUpdate 4.2 for the compat-list version of this). |

## 3. RAUC — update verification doctrine (A/B, boot confirmation)

Sources: https://rauc.readthedocs.io/en/latest/ (index), `basic.html` and `integration.html` (both fetched in full), repo https://github.com/rauc/rauc.

### Stealable patterns

| # | Pattern | RAUC implementation | conwrt mapping |
|---|---|---|---|
| 3.1 | **Boot-confirmation loop (mark-good / mark-bad)** | Update installs to an *inactive* slot; bootloader boots it; the new system runs `rauc status mark-good` only after systemd is up; no signal (or watchdog reset) ⇒ bootloader falls back. "Having written your image data without errors does not mean the system you just installed will really boot." | `flash-rescure`'s missing chapter. After `flash` succeeds: write `pending` to `fire-state`, set U-Boot `BOOT_ORDER`/`BOOT_<slot>_LEFT` (RAUC's exact env contract) or at minimum `bootcount`/`altbootcmd`, then wait for the Linux-boot signature; only then `good`. A/B where the box has dual firmware partitions; on single-image boxes, at least record `pending` so a re-run knows the box may be half-flashed. |
| 3.2 | **Never write the slot you run from; policy for choosing the target** | Slot groups/classes; active-slot detection via `rauc.slot=` kernel cmdline (or `root=` matching); among equivalent inactive groups RAUC picks **oldest install timestamp**. | Recipe safety rule: recipes that write flash must declare `target_mtd` and the engine must cross-check against the card's "currently booted from" MTD (from cmdline or `/proc/mtd` sizes) and refuse self-overwrite unless `--in-rescue` (initramfs/ramboot) is explicit. The hasivo two-phase pattern (TFTP-boot initramfs first, sysupgrade from RAM) is the safe instantiation. |
| 3.3 | **Per-slot status file (sha256) ⇒ skip-if-same** | RAUC hashes each image at bundle time; on install it writes the hash + status to a per-slot/central status file; next install can skip identical images (`install-same=false` to force). | `fire-state`: record `image_sha256` + MTD target per fired recipe. Re-running `flash-rescue` on an already-flashed box: query on-box sha256 gate; if equal, report "already flashed, same image" and exit 0 without touching flash. Cheap, and prevents double-flash during panic. |
| 3.4 | **Handler = f(image type, slot type) matching table** | raw/ext4/nand/nor/ubivol/ubifs… × image extension; invalid combos rejected at plan time, not write time. | Recipe actions should be a registry keyed by (transfer, flash-kind): `tftp+nor`, `raw-serial+nand{oob,noecc}`, `tftp+ubivol`… Unknown combo = load-time error (feeds 1.2). |
| 3.5 | **Verify-as-you-deliver; signing mandatory** | Bundles are signed (X.509/CMS) *by construction*; verity format + HTTP streaming means the payload is hash-verified while being written, no intermediate copy. | `tftp`: compute sha256 host-side *while serving* and assert against the recipe's expected hash at transfer end — closes the gap between "file on disk" and "bytes the box got". Optionally support signed recipes (see SWUpdate 4.1). Note: anti-rollback is **not** native in RAUC (policy left to integrators); SWUpdate is the reference there. |

## 4. SWUpdate — signed pipelines, compat gates, transaction markers

Sources: https://sbabic.github.io/swupdate/swupdate.html, `sw-description.html`, `signed_images.html`, `bootloader_interface.html` (all fetched in full), repo https://github.com/sbabic/swupdate.

### Stealable patterns

| # | Pattern | SWUpdate implementation | conwrt mapping |
|---|---|---|---|
| 4.1 | **Sign the manifest, hash every artifact, verify before touching flash** | Doctrine spelled out: signing the whole compound image means "verification can be done after installing… not safe in case of power off"; signing sub-images alone lets an attacker remix. Chosen design: signed `sw-description` + per-image `sha256` attributes; **missing sha256 on any image = whole SWU not verified, stop before install**; signature check cannot be disabled at runtime. Pipeline order: extract manifest → verify sig → hw-compat → … → stream w/ hash check → bootenv **last**; "first step that fails stops the entire procedure." | Recipe JSON = the manifest. Add optional `signature` (ed25519/minisign) over the recipe, and mandatory `sha256` for every referenced artifact; `--require-signed` mode for fleet use. Keep the SWUpdate ordering discipline in `flash-rescue`: verify → compat → transfer/flash → verify-on-box → **env writes last**. |
| 4.2 | **Hardware compatibility gate** | `hardware-compatibility: ["1.0","1.2"]` incl. `#RE:` regexes, matched against `/etc/hwrevision` (`<board> <rev>`); refuses install on mismatch. Board-specific sections override generic ones via a documented 4-level lookup priority (board.mode.selection first). | Device card + recipe both carry compat lists (`supported: ["gs1900-8hp", "#RE:^gs1900-8"]`); `flash-rescue` refuses unless `serial-detect`'s card matches. SWUpdate's priority chain is the model for card-overlay lookups (board beats chip beats default). |
| 4.3 | **Cross-reboot transaction marker** | Before update: `recovery_status=in_progress` in the bootloader env; unset ⇒ success, `failed` ⇒ failed; plus `ustate` STATE_INSTALLED/STATE_FAILED. Rescue trigger: U-Boot checks GPIO/serial, runs `altbootcmd` to enter SWUpdate; **bootcounter** exceeds limit ⇒ automatic fallback. Env writes are power-cut-safe via redundant env copies (`CONFIG_ENV_OFFSET_REDUND`). | `fire-state` should grow a U-Boot-env mirror: recipe writes `conwrt_rescue=in_progress` (via `setenv`+`saveenv` step) before flash, clears after verified boot. A re-armed `serial-watch` on next power-cycle sees the marker and *knows* it's retrying a half-done rescue — cross-process **and** cross-flash. This is the strongest single steal for the "wedged box" scenario. |
| 4.4 | **Version policy: no-downgrade, no-reinstall** | `-N <ver>` forbids downgrading, `-R` forbids reinstalling same, `install-if-higher` per-artifact, per-update-type policies (OS vs Application with different floors/ceilings); version formats documented (4×16-bit or semver, with "don't mix formats" warning). | Store flashed version (from image metadata) in `fire-state`; `flash-rescue --min-version X` / warn on downgrade with `--force` escape. Low priority for rescue, high for fleet ops. |
| 4.5 | **Handlers as plugins + hooks with atomic file installs** | Handlers register by string type (`raw`, `flash` with `noecc`/`oob` NAND properties, `ubivol`, `rdiff`, `bootloader`…); pre/postinstall scripts (Lua embedded or shell) abort on nonzero; raw file handler writes `.tmp` then renames ("atomic-install"); embedded Lua hooks run *before any handler*. | Recipe action registry (feeds 3.4) with per-action pre/post hooks; any nonzero/absent marker aborts the recipe. Steal `.tmp`+rename for any config files pushed to the box. |

## 5. labgrid — console/place/resource abstractions

Sources: https://labgrid.readthedocs.io/en/latest/configuration.html (fetched in full, incl. drivers/strategies/exporter sections), repo https://github.com/labgrid-project/labgrid.

### Stealable patterns

| # | Pattern | labgrid implementation | conwrt mapping |
|---|---|---|---|
| 5.1 | **Resource → Driver → protocol-based resolution** | `RawSerialPort`/`NetworkSerialPort`(RFC2217 or raw) → `SerialDriver` implements `ConsoleProtocol` → `ShellDriver`/`UBootDriver` depend on *the protocol*, not a class. Swap serial-for-ssh-for-external-console without touching consumers. | Rust trait split in conwrt: `ConsoleSource` (local serial / tcp+IAC / RFC2217) → `Classifier` consumes bytes; `RecipeEngine` consumes `ClassifiedEvent`. Today this is implicit; making it a protocol boundary means e.g. an SSH fallback console or a `socat` external console drops in with zero recipe changes. |
| 5.2 | **Echo-less consoles: marker sandwich** | `SmallUBootDriver` — for stripped U-Boots "without a built-in echo command… uses **'Unknown Command' messages as marker before and after the output** of a command." Also `ShellDriver` docs warn prompt regexes break when shells enable **bracketed paste** (`\x1b[?2004h` must be prefixed to the prompt pattern). | Direct prior art for conwrt's quote-split markers — good, you're in established territory; steal the two extra tricks: (a) "Unknown Command" sandwich as a *fallback marker style* for consoles where echo can't be disabled; (b) harden classifier prompt regexes against bracketed-paste/ANSI escape pollution (strip `\x1b[…]` sequences pre-match). |
| 5.3 | **Strategy = declared FSM with `transition()`** | `UBootStrategy` states {off, uboot, shell, …}; `strategy.transition("shell")` powers on, interrupts autoboot, logs in — recipes/tests ask for a *target state*, not a path. `UBootDriver` params: `bootstring` regex (e.g. `Linux version \d`) to detect handoff, interrupt character, prompt. | `classifier` + `recipe-engine`: formalize the 4 states into a transition-checked FSM and expose `transition_to(UBoot)` — from Linux: `reboot` + interrupt; from silent: power-cycle hook + interrupt; from booting: wait. Recipes become state-independent preconditions ("requires: uboot") instead of assuming what the box is doing. |
| 5.4 | **Stable device identity + power as a first-class resource** | `USBSerialPort: match: {ID_SERIAL_SHORT, ID_USB_INTERFACE_NUM}` — udev-property matching survives re-enumeration; ~30 power backends (PDU families, `uhubctl` USB hubs, Shelly/Tasmota MQTT, GPIO…). | `transport`: accept `match: {ID_SERIAL_SHORT: …}` alongside `/dev/ttyUSB0` (udev on Linux, stable otherwise). `recipe-engine`: add `power_cycle` action with pluggable backends (start with `uhubctl` + HTTP-toggle smartplug à là labgrid's `rest`/`simplerest`). Silent-box rescue loops become fully unattended. |
| 5.5 | **Export resources; keep the coordinator simple** | Exporter config templates remote USB/serial/power resources; coordinator matches places to exported resources with exclusive access. labgrid even wraps UUU and OpenOCD as mere drivers on the same bus. | Long-term: `conwrt export` a console so a second host's `serial-watch` can supervise remotely (you already speak tcp/IAC — mostly a discovery/lock protocol). Near-term: an exclusive lock file so two conwrt processes can't fight over one console across the fire-state boundary. |

## 6. Novelty scan

### 6.1 Event-driven recipe supervisors over serial — surveyed field

| Prior art | Mechanism | vs conwrt |
|---|---|---|
| expect (Tcl) / pexpect (https://pexpect.readthedocs.io/en/latest/overview.html) | Procedural `expect(pattern-list)` loop; EOF/TIMEOUT as pseudo-patterns; `interact()` hands control to human | The classic. Pattern-action, but blocking-read, one-shot, no declarative recipes, no persistent fire-state, spawns subprocesses. conwrt's classifier = their expect-list, run permanently and in-process. |
| labgrid `UBootDriver`/`ShellDriver`/Strategies | Interrupt autoboot, `bootstring` regex, login, marker-based command completion, `transition()` FSM (5.2/5.3) | Closest living relative. But: pytest-centric, procedural Python, no signature-triggered recipe firing, no bundled TFTP/verify gates, not a rescue tool. |
| OpenWrt `scripts/flashing/` (https://github.com/openwrt/openwrt/tree/main/scripts/flashing) | `adam2flash.pl` (ADAM2/FTP), `eva_ramboot.py` (Lantiq EVA RAM-boot), `jungo-image.py`, `flash.sh` | Host-side per-bootloader flashers maintained in-tree — proves demand, all procedural one-shots, no supervision/classifier. |
| NXP UUU / mfgtools (https://github.com/nxp-imx/mfgtools) | `uuu list.uu` command-script files (SDP/FB ops), `-d` daemon waits for device attach, `-s` shell mode | Declarative-ish recipe file + device-wait daemon — but USB SDP protocol, not console signatures; no event classification. |
| Community serial rescues, e.g. https://github.com/ekartashov/hasivo-s1100w-openwrt | Two-phase recipe (U-Boot TFTP initramfs → sysupgrade) written as a README runbook | Exactly conwrt's `flash-rescue` flow, captured as *documentation* a human executes. Validates the workflow; no tooling. |
| OpenWrt wiki serial pages (https://openwrt.org/docs/guide-user/installation/installation_methods/serial), screen+lrzsz gists | Manual procedures, zmodem transfers | Manual; conwrt automates the same lane. |

**Verdict: the combination is novel; the ingredients are not.** No surveyed tool couples (a) a persistent event-driven classifier on the console stream, (b) declarative JSON recipes fired in-process on boot-signature triggers, (c) on-device verification gates, (d) cross-process/cross-reboot fire-state, (e) bundled TFTP + serial fallback, in one supervisor. Individually: pattern-action = expect; echo-proof markers = labgrid SmallUBootDriver; bootdelay-interrupt = labgrid/UBootDriver; event hooks = OpenOCD; transaction markers = SWUpdate; declarative update manifests = RAUC/SWUpdate; recipe-file + device-wait = UUU. Claim novelty on the **supervisor composition aimed at rescue**, not on any single mechanism — and expect labgrid to remain the nearest neighbor reviewers will name.

### 6.2 Hybrid scripted/AI-prompted diagnostics ("AI proposes, deterministic engine executes")

The doctrine exists and is mature — in ops, not on serial consoles:

- **HolmesGPT** (https://holmesgpt.dev, https://github.com/HolmesGPT/holmesgpt): SRE agent whose core primitive is a **runbook catalog** — "step-by-step troubleshooting guides that Holmes follows… automatically matches relevant runbooks from its catalog and fetches them" (https://holmesgpt.dev/0.24.1/reference/runbooks/). The lesson its users report: "the runbooks mattered more than the model" (CNCF blog, https://www.cncf.io/blog/2026/04/21/auto-diagnosing-kubernetes-alerts-with-holmesgpt-and-cncf-tools/).
- **k8sgpt** (via same sources): deterministic analyzers first, AI only explains; **Kato**: "deterministic runbooks with AI at the end" (https://sakul-learning.github.io/2026/06/14/kato-kubernetes-troubleshooting-workflows/).
- Generic terminal LLM agents (terminal-agent, AI Shell Agent, etc.) exist aplenty, but none bound to a hardware console with safety gates.

**Verdict: unclaimed for embedded/serial.** `conwrt advise` (AI matcher over a *recipe catalog* + device card + recent transcript; engine schema-validates and executes; destructive steps human-confirmed) would be a genuine first — provided you copy the HolmesGPT shape (AI selects/parameterizes from a constrained catalog; it never emits free-form console commands).

## 7. Prioritized top-10 improvements for conwrt

| # | Improvement | Steal from | Module | Priority |
|---|---|---|---|---|
| 1 | **Rescue transaction marker + boot confirmation**: `pending → verified-boot → good` states; write `conwrt_rescue=in_progress` to U-Boot env before flash, clear after Linux signature; on re-arm, marker tells serial-watch it's resuming a half-done rescue; set `bootcount`/`altbootcmd` (or RAUC-style `BOOT_ORDER`/`BOOT_x_LEFT`) when dual-firmware slots exist | SWUpdate 4.3, RAUC 3.1 | fire-state, recipe-engine | **P0** |
| 2 | **Pre-flight gate block**: recipe `supported` list (incl. `#RE:` regex) matched against serial-detect card; per-artifact `sha256` mandatory; image-vs-MTD-layout size/arch check; optional recipe signature (`--require-signed`); order: verify → compat → transfer → flash → env-writes-last | SWUpdate 4.1/4.2, esptool 2.5 | flash-rescue | **P0** |
| 3 | **Chunk protocol hardening for raw-serial fallback**: per-chunk seq + CRC32 with chunk-level retry, negotiated block size, in-flight window, resume-from-offset ledger in fire-state; final whole-range on-box sha256 stays authoritative | esptool 2.3/2.4 | raw-transfer | **P0** |
| 4 | **Validate-then-arm lifecycle**: full recipe+card validation and lock before console open; classifier states as explicit FSM with `transition_to(state)` and `on_enter_*` / `on_silent_timeout` event triggers; recipes declare `requires: <state>` | OpenOCD 1.2/1.3, labgrid 5.3 | recipe-engine, classifier | **P1** |
| 5 | **Compositional device cards**: `chip → board → revision` fragments with override variables and `find`-style search path (shipped + user dir); detection ends in assert-report (expected vs seen, per-field) | OpenOCD 1.1/1.4 | serial-detect | **P1** |
| 6 | **Action/handler registry keyed by (transfer × flash-kind)**: `tftp+nor`, `raw-serial+nand{oob,noecc}`, `tftp+ubivol`…; per-action pre/post hooks with abort-on-fail; unknown combo = load error | RAUC 3.4, SWUpdate 4.5 | recipe-engine | **P1** |
| 7 | **Power as a resource**: `power_cycle` recipe action + backends (uhubctl, HTTP smartplug, PDU); udev `ID_SERIAL_SHORT` matching for stable console identity; auto power-cycle loop on silent-timeout | labgrid 5.4 | transport, recipe-engine | **P1** |
| 8 | **Control surface**: TCP/JSON status+fire+event-subscribe port; console lock file; later `conwrt export` for remote supervision | OpenOCD 1.5, labgrid 5.5 | serial-watch | **P2** |
| 9 | **Marker & parser robustness**: "Unknown Command" sandwich as fallback marker style; strip ANSI/bracketed-paste (`\x1b[?2004h`) before signature matching; document the CR/LF stream-matching traps pexpect documents | labgrid 5.2, pexpect docs | classifier, markers | **P2** |
| 10 | **`conwrt advise`**: LLM matches+parameterizes recipes from the catalog given transcript+device card; schema-validated; human confirms destructive steps; AI never emits raw commands | HolmesGPT runbooks (6.2) | new | **P2** (novelty upside) |

Dropped-explicitly (considered, rejected for now): on-box stub helper beyond verify (esptool 2.2) — fold into #3 later; delta/adaptive transfers (RAUC/SWUpdate rdiff) — irrelevant at rescue sizes; full labgrid coordinator — #8's lock is enough until multi-bench.
