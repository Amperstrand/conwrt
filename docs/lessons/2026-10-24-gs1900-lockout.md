# Lesson learned: how the gs1900-8hp locked us out (2026-10-21 → 2026-10-24)

The full postmortem of a 3-day lockout that ended in a successful
agentless recovery. Written so the next box never gets here.

## What locked us out

**The trigger — a config, not a kernel:** the fleet's instrumented
builds carried an SVI alias overlapping the routed management subnet
(the ".13.x alias door": `ip addr add <bench-mgmt-ip>/24 dev switch.1008`
while <bench-mgmt-subnet>/24 was already routed on VLAN13). This trips an
rtl83xx L3-offload bug (upstream openwrt/openwrt#26061:
`otto_l3_fib_event_work_do` → `otto_l3_fib_add_v4` under rtnl_lock).

**Why it became a lockout:** the killer alias lived in the FLASHED
CONFIG, so every boot re-applied it at procd/netifd time (~10-18 s in):
network stack dies, kernel stays alive, console input degrades in
stages (responsive → byte-mangled → dead), getty starves, dropbear
never binds. Every "image-specific wedge" theory died when a different
instrumented build (6.12.94 vs 6.12.108) wedged identically and both
pristine releases booted clean — it was a CONFIG-line pattern, not a
build-line pattern.

**Root rules that would have prevented it:**
1. Never configure a subnet on an SVI/alias overlapping any routed
   prefix on the box. `tools/svi_preflight.sh` exists — run it before
   every alias add. The .13.x alias door is banned.
2. The upstream bug remains open: any overlapping config can wedge any
   kernel with this driver. Config hygiene is the only defense.

## What WE did that deepened the hole

1. **We chose the wrong transport for big images.** We streamed the
   6.5 MB sysupgrade image raw over the 115200 console (27 min at
   ~4-6 KiB/s). Four of four such streams ended in a box death at/after
   stream end (UART stuck echo-looping image bytes on the final one) —
   sustained RX saturation followed by CPU-heavy sha compute. Every
   ACK-paced YMODEM transfer (3/3) survived. Community practice
   (forum 57875, device commit messages) never streams raw images:
   ethernet carries bytes, serial carries steering. We re-derived that
   the hard way.
2. **We burned a 1-second bootdelay window on wrong-order probes**
   (shell probes before the space press). Time-critical phases must run
   the instant their trigger matches, in the watching process itself
   (now: `conwrt serial-watch`).
3. **We left host round-trips in the post-transfer gap** where the box
   died twice before we armed verification+action ON BOX (the
   self-firing receiver doctrine).

## What recovered it

Direct wire (switch lan port ↔ host NIC) + U-Boot's own network stack:
`rtk network on` → `tftpboot` (5.29 MB in ~8 s, byte-count gated) →
`bootm` → initramfs → `wget` sysupgrade over the same wire → on-box
sha gate → `sysupgrade -n` (wipes the killer config). Serial moved a
few command lines total. Zero wedge ticks after; 192.168.1.1 answering
pings. All of it now codified: recipes + `tftp_boot` action + bundled
read-only TFTP server (PR #545).

## Failure-depth taxonomy (learned in live testing, 2026-10-24 night)

Three distinct "dead console" depths, each with a different recovery:

1. **Config-wedge** (kernel alive, network/L3 dead): console input
   degrades but BREAK+sysrq-b still resets. conwrt serial-recover's
   native case — 25+ field uses.
2. **Echo-storm lockup** (self-inflicted: binary fed to an echo-on tty):
   console goes silent BUT the box self-heals once the backlog drains
   — wait for quiet, then probe. DANGER: the draining backlog replays
   stale text that can false-trigger watchers — fire-markers must live
   on disk (`<transcript>.fired`), cooldown spanning processes.
3. **CPU hard-lock** (printk/8250 lockup class, SUSE KB 7025302): even
   BREAK+sysrq gets zero response — only power clears it. Caused by
   console TX storms / saturated RX + concurrent printk. Prevention:
   never stream before a verified raw-mode handshake (RDY), never let
   the shell echo binary, ACK-pace or chunk everything.

## The one-line version

A banned config alias wedged every boot via a known upstream driver
bug, and we spent a day forcing big images over a console link that
dies under sustained load — the fix was ethernet for bytes, serial for
steering, verification on-box, and a watcher that never blinks.
