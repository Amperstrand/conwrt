## Why this matters

Community consensus: modem firmware `BD_TELIAMF286DV1.0.0B14` (the
"Nordic_B14" package, Oct 2024) breaks QMI data under OpenWrt while B12 is
the known-good. Nobody has root-caused it. Our B12 modem RE (EXP-034) proved
the platform keeps policy in **runtime NV data** (cfg_service.db), not
compiled code — and community evidence shows the B14 update **ships an NV
script**. The B14 breakage is therefore probably one or more NV items, i.e.
potentially fixable without any firmware change. That would answer
ddimension/wwand PR #85 (obsy's question) with evidence.

## Evidence base (verified sources)

- Symptom matrix (B14 under OpenWrt 24.10, user "luca", 2025-03-03):
  https://forum.openwrt.org/t/zte-mf286d-internal-4g-modem/175362
  - Works: AT ports, QMI UIM (SIM ready), QMI NAS (registered), DMS, WDA
    raw-ip. Broken: QMI WDS `--start-network` hangs → "Unknown error"
    (PAP/CHAP, ipv4, ipv4v6 all fail); `--stop-network 0xffffffff
    --autoconnect` → "No effect"; voice; 3G (NV-disabled).
  - KEY: `AT+CGPADDR` showed THREE ACTIVE PDP contexts (real IPs) while
    `--get-current-settings` said "Out of call" → the modem's data engine
    runs sessions QMI WDS cannot see/stop/start.
- eko.one.pl thread "Modem od routera MF286D" (id=21790), esp. posts ~791,
  803-823: https://eko.one.pl/forum/viewtopic.php?id=21790
  - B14 package sets modem NV: users extracted from the `.up`:
    `nv set net_select="Only_LTE"`, `nv set default_lte_band_lock=0x2008080045`,
    `nv set default_gw_band_lock="0x2000000400000"`, `nv set lte_band_lock=…`,
    `nv set gw_band_lock=…` (fragment only — get the FULL script).
  - Router-side version identity is NV-CACHED: after flashing B12 mtd8/9 over
    B14, ZTE UI still reported B14/B02 until factory defaults were restored
    (post 803/804). More runtime-data-not-code evidence.
  - Community ADB trick on B14-era units (unsuccessful but evidence ADB
    survives): `adb shell usr/bin/qmi_shutdown_modem` + `adb usb`
    → modem-side binary `/usr/bin/qmi_shutdown_modem` exists.
  - Wiki note (added 2025-03-03): do not upgrade modem to B14.
- Naming trap: Nordic_B14 = router `V1.0.1B02` + modem `BD_…B14`. Delta
  filename is `TELIA_MF286DV1.0.0B12-TELIA_MF286DV1.0.1B02.up`. The wiki
  note's "B02" vs "B14" confusion is this naming, not different firmware.
- B14 vs B12 feature history (ispreview thread 42622): B11 modem = VoLTE
  enable; B12 = upload carrier aggregation; B14 = unpublished (security
  bundle on router side: CVE-2023-25649 fix per our firmware matrix).

## Our hypothesis (to test, not assume)

B14's NV script (or new firmware defaults) flips the modem to
internal-autoconnect / proprietary data-path management: the modem holds its
own PDP contexts; external QMI WDS control conflicts → every third-party
stack (uqmi, ModemManager, wwand QMI backend) fails identically. Stock
firmware works with B14 (different, ZTE-internal bring-up path).
